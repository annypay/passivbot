# g4 @ TWE 3.0 的账户级守护实测（2026-09-17）

**一句话结论：你要的这条“一周内浮亏 20% ⇒ 熔断 12H、第二次再熔断 24H”在本地历史里确实把账户从强平线上救回来了**
（5.4 年腿：无守护臂 2021-05-19 被强平、终值 0.71×；直译守护臂 **7.86×**、最差回撤 62.40%），
**但它必须在 20% 就 panic 清仓**；“只停加仓、不砍仓”的软刹车版本在 TWE 3.0 上**与无守护一样被强平**；
而带“累计 40% 永久停机”的阶梯近似版**在第一次触发就被永久锁死**（活下来，但 5.32 年再没交易）。
温和的 3 年腿上，这条守护的代价是**终值 8.83× → 6.22×（−30%）**，回撤几乎没改善（31.60% → 30.19%）。

> 12 个 arm、两条腿、全部离线重放；每个 arm 的完整深度分析在其 run 目录的 `annual_analysis.md`，
> 跨 arm 综合见 [`account_guard_analysis.md`](account_guard_analysis.md)，
> 引擎级增强方案见 [`account_guard_design.md`](account_guard_design.md)。

## 你的条件 → 引擎口径映射

| 你的条件 | 本轮实现 | 配置 |
|---|---|---|
| 账户级（不是单币） | `unified` 作用域 | `live.hsl_signal_mode=unified` + `bot.long.hsl.enabled=true` |
| 一周内 | 滚动峰值窗口 7 天 | `live.pnls_max_lookback_days=7.0`（分母 = 一周内最高策略权益） |
| 浮亏 20% | RED 阈值 0.20 | `bot.long.hsl.red_threshold=0.20`（触发指标 `min(raw, EMA)`） |
| 立即反应 | 快速 EMA | `bot.long.hsl.ema_span_minutes=60`（默认 720 正是上一轮 0 次触发的原因） |
| 熔断 12H / 第二次 24H | 停机时长（引擎是**单一常量**） | `cooldown_minutes_after_red=720`（12H）/ `1440`（24H） |
| 第二次按**剩余余额**再算 20% | episode 结束后滚动峰值清空 | 无需配置，引擎天然如此 |
| 阶梯升级（12H→24H） | 引擎无法表达，用终局阈值近似 | `restart_after_red_policy=threshold` + `no_restart_drawdown_threshold` |

**引擎语义（已逐条在代码里核实）**：YELLOW 仅遥测；**ORANGE = 整个作用域进 TpOnly（不产生任何新入场、含加仓，只走止盈）**；
**RED = 先 panic 平掉整个作用域，再停机**。所以在这套引擎里“熔断”= **实现亏损 + 离场**，
不存在“停机但保留仓位”的中间态；想“不砍仓只停加仓”，只能用 ORANGE 表达（本轮做了这个对照）。

| arm（×2 条腿） | 守护配置 | 检验什么 |
|---|---|---|
| `g_user12h` | unified，RED 0.20 / ORANGE 0.15 / EMA 60 / 停 12H / 不锁存 | **你的直译条件** |
| `g_user24h` | 同上，停 24H | 停机时长翻倍是否更安全 |
| `g_ladder40` | 同上 + 累计回撤 0.40 永久停机 | “第二次升级”的引擎近似 |
| `g_soft_orange` | ORANGE 0.20（停加仓）/ RED 0.35 / 停 24H / 0.45 锁存 | **软刹车**：先停加仓、深了才砍 |
| `g_orange_only` | ORANGE 0.20 / RED 0.60 / 停 12H | 极端软刹车：只停加仓，几乎不砍 |
| `g_slow_ema` | 与 `g_user12h` 同，仅 EMA 720 分钟 | 反证：触发速度是不是必要条件 |

两条腿：原生窗口（2023-09-12 → 2026-09-12）与 5.4 年历史压力腿（2021-04-20 → 2026-09-13，2021-05 崩盘在其中）。
控制臂是上一轮的两条无守护运行（`twe300_10k__3y` / `twe300_10k__ext`），`analysis.json` sha256 已钉住、不重跑。

## 结果一：全期指标

| arm | 3 年腿 终值 / 最差回撤 | 5.4 年腿 终值 / 最差回撤 | 强平 |
|---|---|---|---|
| 无守护（控制臂） | 8.8346× / 31.60% | **0.7139× / 95.34%** | **是**（2021-05-19 12:53Z，存活 29.5 天） |
| `g_user12h` | 6.2161× / 30.19% | **7.8552× / 62.40%** | 否 |
| `g_user24h` | 6.1234× / 30.19% | 7.6984× / 62.77% | 否 |
| `g_ladder40` | 6.2161× / 30.19% | 0.5695× / 57.57% | 否，但**终局停机**（2021-05-19 后再未交易） |
| `g_soft_orange` | 8.6169× / 31.59% | 0.7139× / 95.34% | **是** |
| `g_orange_only` | 8.6169× / 31.59% | 0.7139× / 95.34% | **是** |
| `g_slow_ema` | 6.3733× / 31.59% | 0.7139× / 95.34% | **是** |

- 三条**软刹车 / 慢触发**臂在历史腿上的终值与无守护臂**逐位相同**（443 笔成交的 时间戳/币/类型 逐笔一致，
  `gain_strategy_eq = 0.71391913274802` 完全相同）：`hard_stop_triggers = 0`，
  即它们**一次都没触发就已经强平**——不是“效果差”，而是“根本没来得及”。
- 直译守护臂在 2021-05-19 **12:47** 完成 panic 清仓，比无守护臂触及地板（12:53）**早 6 分钟**。
- 守护把 95.34% 的回撤压到 62.40%，但**仍然是 62%**：它换的是“不被清零”，不是“安全”。

## 结果二：整装待发读数（逐次停机）

| arm | 停机 | 逐次时长 | 停机时权益 | 复牌后 7 天 | 复牌后 30 天 | 声明 vs 实际离场 |
|---|---|---|---|---|---|---|
| `g_user12h__ext` | 5 次 | 5 × 11h | 5,695 → 4,838 → 9,354 → 9,366 → 69,286 | 均值 +0.65%（首次 −13.51%） | 均值 +2.72% | 声明 60h / 实际 55h |
| `g_user24h__ext` | 5 次 | 27h / 41h / 26h / 24h / 23h | 同上 | 均值 +0.12%（首次 −14.51%） | 均值 +2.12% | 声明 120h / 实际 141h（最长多等 17h） |
| `g_ladder40__ext` | **1 次（终局）** | 46,618h（≈1942 天，占窗口 98.5%） | 5,695 | n/a（再未交易） | n/a | 声明 46,619h（引擎 `duration_max`） |
| 3 年腿守护臂 | 各 1 次 | 11h / 23h | 55,185 | +3.0% ~ +4.5% | +5.7% ~ +7.3% | 声明 12h/24h，实际 −1 个采样格 |

读法：
1. **复牌不是“接着赚”，而是“接着被打”**：2021-05-19 第一次复牌后 7 天是 **−13.5%**，4 天后第二次触发（05-23）。
   这就是“整装待发”的真实成本；第二次复牌后 7 天才转正（+7.8%）。
2. **停机时长 ≠ 离场时长**：24H 臂的 05-23 那次，冷却 24h 到期后**又空仓等了 17h** 才等到入场信号，
   实际离场 41h（离场/声明 = 1.18）。用“熔断 24H”估算资金占用会偏低。
3. **终局锁存是这套引擎里最危险的一格**：`no_restart_drawdown_threshold=0.40` 在 `g_ladder40__ext` 上
   **第一次触发就锁死**——触发线是 20%，但锁存判定发生在 panic 平仓确认那一刻、用的是 `max(raw, EMA)`，
   当时确认回撤已经 46.9% ≥ 0.40。账户活到窗口末，却是**一具尸体**（0.57×、5.32 年零交易）。

## 判据裁决（预注册 J1–J5）

| 判据 | 裁决 |
|---|---|
| **J1** 任一守护臂在历史腿活到窗口末 | **通过**：`g_user12h__ext`、`g_user24h__ext`、`g_ladder40__ext` 均未强平；但后者是终局停机 |
| **J2** 3 年腿回撤 ≤ 基线 ×0.8 且 CAGR ≥ 基线 −30pp | **未通过**（回撤只到 30.19% vs 基线 31.60%，CAGR 83.84% vs 106.69%） |
| **J3** 24H 停机不更差 ⇒ 阶梯升级值得做 | **两腿均为“更差”**（复牌后 7 天更差；ext 腿回撤也更差）⇒ 单纯拉长冷却没有证据支持 |
| **J4** 软刹车（分级）双优于直译版 | **未双优**：3 年腿省下 28pp 终值，但历史腿直接强平 |
| **J5** 慢 EMA 触发不足 ⇒ 触发速度是必要条件 | **通过**：EMA 720 分钟在历史腿 0 次触发、强平；3 年腿与直译版几乎相同 |

## 关键机制发现（这一轮真正学到的东西）

1. **TWE 3.0 满仓到强平地板只有约 −31.8%**：任何“等浮亏到 X% 再动手”的账户级止损，其可保险区间就是
   `X%` 到 `31.8%`。跳空超过这个区间，止损来不及——**结构（TWE / `n_positions` / `we_excess_allowance_pct`）
   是唯一确定性的尾部防线**。
2. **“只停加仓”不是黑天鹅防线**：ORANGE=TpOnly 只阻止**新**入场，已经堆到 3× 的仓位照样跟着崩盘走到地板
   （`g_orange_only__ext`、`g_soft_orange__ext` 与无守护臂逐笔相同）。它只在“慢跌”里有用。
3. **触发速度是必要条件**（J5）：EMA 720 分钟的同一套阈值在历史腿一次都没触发。20% 这条线要配 **EMA 60 分钟**级的速度。
4. **锁存阈值必须高于“一次急跌的确认回撤”**：否则第一次触发就把账户永久关停（见上）。
5. **熔断的方向性风险**：panic 清仓把浮亏变成实亏，且通常落在最坏的时点（本轮 12H 臂在 05-19 清仓复牌后，
   7 天内又吃了 −13.5%，随后 4 天内的第二次触发把仓位再次清在更低点）—— “先活下来”的代价是
   **用接近最低点的价格换来生存**，这一点在回测里是可见的成本，不是模型误差。

## 建议（按优先级）

1. **先做结构性去风险，再谈熔断**：上一轮已验证 `we_excess_allowance_pct=0` 在同一条历史腿上**未被强平**
   （14.29×、最差回撤 92.22%），终值高于本轮任何守护臂，而且不需要盯盘。**不要用 TWE 3.0 实盘。**
2. **若一定要在 TWE 3.0 上跑，采用直译守护**：`unified` + RED 0.20 + ORANGE 0.15 + EMA 60 + 停 12H + **不锁存**
   （`no_restart_drawdown_threshold=1.0`）。这是本轮唯一“把强平变成生存”的配置，代价是 3 年腿终值 −30%。
3. **不要用“累计 40% 永久停机”这类锁存做阶梯**（本轮已证伪其安全性）：要阶梯，就把阶梯做在**冷却时长**上，
   而不是一次性关停；设计见 `account_guard_design.md`。
4. **不要用 ORANGE 当黑天鹅防线**，它只是加仓节奏控制。
5. **引擎级增强需要独立 PR**：阶梯冷却（12h→24h→72h）、冷却后分级复入、按已实现亏损的预算式停机、
   与日线闸门联动，都在 `account_guard_design.md` 里给了状态机、实盘重建契约与测试矩阵。

`guard_readiness.json` 的口径：停机窗口 = **紧跟 panic 平仓（≤180 分钟）**之后、权益恒定（容差 1e-6 USDT）
且无成交的连续段；结束后有成交 = 完整停机（窗口止于复牌成交），结束后再无成交 = **终局停机**（窗口止于回测结束）。
窗口长度与 `cooldown_minutes_after_red`（终局停机则与 `hard_stop_duration_minutes_max`）比较，
容差取两个采样格（120 分钟）；比声明长的部分单独记为“停机结束后等待入场信号的空仓时间”。
`cross_check_problems` 只在这些关系**不可能成立**时才报错（窗口数与 `hard_stop_triggers` 不符、
窗口短于声明停机、终局停机与重启次数矛盾、总停机时间与 `hard_stop_time_in_red_pct × 窗口` 不符）。

## 边界（必须一起读）

- 任何账户级止损都挡不住“超过到强平距离的跳空”：TWE 3.0 满仓只有 −31.8% 的缓冲。
- 引擎的冷却时长是**单一常量**，无法表达“第二次自动升级为 24H”；本轮用终局阈值做近似并已证伪其安全性。
- RED = 先清仓再停机，因此“熔断”必然把浮亏变实亏；“停机但保留仓位”在这套引擎里不可表达。
- “浮亏 20%”在引擎口径下是“策略权益相对 **7 天滚动峰值**回撤 20%”，**包含已实现亏损**，比纯未实现亏损更保守；
  报告中的“停机起点回撤”是**全期运行峰值**口径，两者分母不同、不可混读。
- 历史范围有限：币池是活到 2026 年的当前 top40（幸存者偏差）；5.4 年腿 2021-04-20 起交易，
  当时仅 22 个币有数据；2021-05 事件落在闸门首次风险开启后 3 个交易日。
- 未建模：真实资金费率、滑点枯竭、API 断连、交易所/稳定币对手方风险；引擎不模拟保证金占用。
