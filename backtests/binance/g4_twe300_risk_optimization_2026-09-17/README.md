# g4 @ TWE 3.0 的风险几何优化：占用纪律、冷却档位与参数搜索（2026-09-17）

**一句话结论：`we_excess_allowance_pct = 0`（不让任何币占用空槽的额度）在机制上完全按预期生效——
单币上限 0.5871 → 0.4286、单币归零上界 59.15% → 44.34%、温和 3 年窗最差回撤 30.19% → 23.05%——
但在同一档杠杆（TWE 3.0）上把它叠在账户级守护之上时，它在崩盘腿上反而更差：终值 2.30× vs 7.86×、
最差回撤 76.56% vs 62.40%。两条保护是"替代品"而不是"叠加品"：无守护时 allowance=0 是救命的那一条
（14.29× 未被强平），有守护时 allowance=0.37 才是更好的那一条。冷却档位则再次证伪：24/48/72H 在两条腿上
都不优于 12H；累计永久阈值 0.55/0.70 依旧在崩盘里把关停提前到第一/第二次触发（0.34× / 0.29×）。**

> 44 个 arm（32 个声明式 + 12 个搜索候选）在三条腿（搜索窗 3y、全历史 ext、样本外 pre）上重放；
> 每个 arm 的完整深度分析在其 run 目录的 `annual_analysis.md`；跨 arm 综合见
> [`risk_geometry_analysis.md`](risk_geometry_analysis.md)；本轮设计与下一轮引擎阶梯的定档见
> [`variant_geometry_design.md`](variant_geometry_design.md)。

## 1. 这轮在回答什么

前三轮已经收敛：**TWE 3.0 / 10,000 USDT 会被强平；账户级守护能救回来但很贵**（3 年腿终值 8.83× → 6.22×）。
本轮把变量严格限制在**风险几何**上，问能不能把这份生存买得更便宜：

| 你的方向 | 本轮实现 | 结果 |
|---|---|---|
| 占用纪律：不占用空槽的额度 | `we_excess_allowance_pct = 0` | 机制生效（集中度、单币上界、温和窗回撤全部改善），但与守护叠加时崩盘腿更差 |
| 阶梯接在冷却时长上 | 固定档位 12/24/48/72H + 累计阈值二档 + 实现亏损刹车 | 档位越长越差；累计阈值再次首击锁存；实现亏损刹车**零效果** |
| 用现有基础设施优化参数 | 仓库 pymoo 优化器，只搜 6 个风险几何维度，alpha 全部钉死 | 搜索窗最优点（c1）在样本外**被强平**；c4 收益更好但回撤 80%，按预注册判据未通过 |

## 2. 三条腿与占用纪律的确切含义

| 腿 | 窗口 | 角色 |
|---|---|---|
| `3y` | 2023-09-12 → 2026-09-12 | **搜索窗（样本内）** |
| `ext` | 2021-04-20 → 2026-09-13 | 全历史（含搜索窗；只有 2021-05 崩盘段算样本外） |
| `pre` | 2021-04-20 → 2023-09-11 | **样本外验收窗**（`intersection` override 从同一份长 bundle 切出，与搜索窗不重叠） |

引擎的单币上限是 `TWE / n_positions × (1 + effective allowance)`，bounded 模式下
`effective = min(raw, TWE/(TWE/n) − 1)`（本域内 = `n_positions − 1`，不 binding）。于是：

- `allowance = 0.37`（父配置）⇒ 单币上限 = 均分额度 × 1.37 = **0.5871**（TWE 3.0 / 7 槽）；
- `allowance = 0` ⇒ 单币上限 = 均分额度 = **0.4286**，但总暴露上界不变。

**一个必须一起读的实测细节**：上限是"下单规划时"的约束；成交账本记录成交时的 `wallet_exposure`，
盯市漂移与**交易所最小下单量**会让实测略高于上限。本轮 32 个声明式臂里最大绝对超出 0.0191
（最紧的上限 TWE 2.5/7 槽），相对最高 +5.47%。几何不变量因此用 `上限 × 1.05 + 0.02` 校验，
造成超出的那笔成交记在 `risk_geometry.json` 的 `cap_overshoot_fill` 里（例如 AVAX 的 1 张最小加仓）。

## 3. 结果一：占用纪律（ext 腿，守护都是 unified 0.20 / EMA 60 / 停 12H）

| arm | allowance | TWE | 终值 | 最差回撤 | 峰值单币敞口 | 单币归零上界 | 在场币数均值 |
|---|---|---|---|---|---|---|---|
| 守护基准（上一轮，钉住） | 0.37 | 3.0 | **7.8552×** | **62.40%** | 0.5915 | 59.15% | 2.86 |
| `a_allow020` | 0.20 | 3.0 | 3.0353× | 78.39% | 0.5258 | 52.58% | 2.87 |
| `a_allow010` | 0.10 | 3.0 | 2.6644× | 74.07% | 0.4840 | 48.40% | 2.90 |
| `a_allow000` | **0** | 3.0 | 2.3002× | 76.56% | **0.4434** | **44.34%** | 2.87 |
| `a_allow000_twe250` | 0 | 2.5 | 1.6180× | 80.14% | 0.3763 | 37.63% | 2.87 |
| `a_allow000_twe200` | 0 | 2.0 | 1.9500× | **61.60%** | 0.3014 | 30.14% | 2.87 |
| `b_red015`（allowance 0 + RED 0.15） | 0 | 3.0 | **4.3033×** | **56.52%** | 0.4305 | 43.05% | 2.86 |

温和 3 年腿（搜索窗）：`a_allow000` 4.68× / **23.05%**、`a_allow000_twe250` 3.67× / **19.20%**、
`a_allow000_twe200` 2.81× / **17.75%**，而守护基准 `g_user12h__3y` 是 6.22× / 30.19%——
**在良性窗口上，占用纪律确实把回撤压下来了**（30.19% → 23.05% → 17.75%），代价是终值。

**判据 J1（占用纪律有效性）：无效。** 四项检查里"峰值单币敞口更低"与"单币归零上界更低"通过，
"终值不低于基准 80%"与"最差回撤不更高"未通过。机制解释：更紧的单币上限让每次清仓后的重建更慢，
而且改变了权益路径、推迟了守护的触发时点，于是崩盘腿的回撤反而更深（76.56% vs 62.40%）。
**在场币数在两种 allowance 下几乎不变（2.86 vs 2.87）**——"占用纪律"改变的是每个币的**大小**，不是持有的**数量**。

**判据 J2（占用×杠杆，样本外腿）**：pre 腿上 `a_allow037__pre`（1.2506× / 62.40%）优于
`a_allow000__pre`（0.6104× / 76.56%）与 `a_allow000_twe250__pre`（0.4242× / 80.14%）⇒
**推荐设置是"保持 allowance 0.37 + 守护"**，即在守护已开启时不要收占用余量。

## 4. 结果二：冷却档位、累计二档与实现亏损刹车

| arm（allowance 0） | ext 终值 / 最差回撤 | pre 终值 / 最差回撤 | 结论 |
|---|---|---|---|
| `b_cool24`（停 24H） | 2.7662× / 76.85% | 0.5888× / 76.85% | 不优于 12H |
| `b_cool48`（停 48H） | 2.0828× / 77.10% | 0.5554× / 77.10% | 更差 |
| `b_cool72`（停 72H） | 1.8666× / 79.29% | 0.4832× / 79.29% | 更差 |
| `b_term055`（累计 0.55 永久停机） | 0.3399× / 67.85% | — | **首击锁存**（1 次停机后永久退出） |
| `b_term070`（累计 0.70 永久停机） | 0.2910× / 76.56% | — | 第二次触发锁存，同样死掉 |
| `b_lossgate050`（实现亏损刹车 0.50） | 2.3002× / 76.56% | — | 与未开启**逐笔相同**（45,644 笔成交签名一致）⇒ 零效果 |
| `b_ema15`（EMA 15 分钟） | 1.7814× / 68.35% | — | 触发更快=更多停机（7 次），回撤改善但收益受损 |
| `b_red015`（RED 0.15） | **4.3033× / 56.52%** | — | 同一几何下最优点：更早熔断同时改善收益与回撤 |

**J3：加长冷却不是收益杠杆**（档位越高，两条腿都更差）⇒ 下一轮引擎阶梯的最高档取 **24H**，
并把阶梯明确定义为"风险塑形、默认关闭"（写入 `account_guard_design.md` §6.3）。
**J4：累计二档证伪**——0.55/0.70 都会在这段历史里把账户提前关停；任何低于存活臂最差回撤（76.56%）
的永久地板都等于自杀，永久停机应改用**累计已实现亏损**口径。

## 5. 结果三：参数搜索（现有 pymoo 优化器）

搜索契约冻结在 `artifacts/variant_input.json`：只搜 6 个风险几何维度
（TWE ∈ [2.0,3.0]、`n_positions` ∈ [5,10]、allowance ∈ [0,0.37]、RED ∈ [0.15,0.35]、
EMA ∈ [15,120]、冷却 ∈ [720,4320]），alpha 全部用 `-ft/--fine-tune-params` 钉死
（运行日志里的 tunable 集合必须恰好是这 6 个，否则 `run_search.py` 判失败）；
双目标（ADG 最大 / 最差回撤最小）+ 参考约束（回撤 >0.60、completion <0.99 惩罚）；
选臂规则在看到样本外结果之前执行。

**预算如实降级**：声明的预算最初是 `iters=1024 / population=64 / n_cpus=2`。冒烟测（16 iters / 8 人口 / 2 worker）
实测到本机的真实行为：**49 次精确评估耗时 12.6 小时、峰值 RSS 6196 MB**（前 41 次约 12 分钟，
之后内存压力下最后 8 次耗时 12 小时），即声明预算在本机不可行。因此本轮按冒烟测的
**49 次评估 Pareto 前沿**（8 个候选）用**未改动的选臂规则**冻结了 4 个候选（`c1`–`c4`），
并在报告与 `issue/0006` 里如实标注这一降级。

| 候选（来源） | TWE / 槽位 / allowance / RED / EMA / 停 | 3y（搜索窗） | ext | pre（样本外） |
|---|---|---|---|---|
| `c1`（max ADG） | 2.80 / 6 / 0.21 / 0.30 / 75 / 4320 | **7.2577× / 25.01%** | 0.7118× / 95.31% **强平** | 0.7118× / 95.31% **强平** |
| `c2`（min DD） | 2.10 / 10 / 0.06 / 0.34 / 15 / 2880 | 2.5735× / **19.01%** | 1.3018× / 78.03% | 0.4780× / 78.03% |
| `c3`（拐点补充） | 2.40 / 6 / 0.21 / 0.23 / 60 / 720 | 5.4503× / 21.43% | 2.3313× / 88.77% | 0.4128× / 88.77% |
| `c4`（拐点补充） | 2.25 / 6 / 0.22 / 0.34 / 120 / 2880 | 4.9378× / 20.25% | **9.0111× / 79.99%** | **1.7789× / 79.99%** |

**J5：搜索未找到更优点（预算受限）。** 预注册的严格门是"ext ≥ 7.8552× 且 pre 未强平且 DD ≤ 50%"：
`c4` 在收益上确实超过了守护基准（9.01× vs 7.86×，pre 腿 1.78× vs 1.25×），但它的样本外回撤是 79.99%
（> 50% 的门），所以按规则判为未通过；而搜索窗里收益最高的 `c1` **在样本外被强平**——
这正是"样本内最优 ≠ 样本外可用"的教科书案例，也是本轮坚持设样本外腿的原因。
`c4` 因此在本报告里被记录为**Pareto 点**（更高收益、更深回撤），而不是"更优解"。

## 6. 判据裁决（预注册 J1–J6）

| 判据 | 裁决 |
|---|---|
| **J1** 占用纪律有效性 | **无效**（集中度两项通过；终值与回撤两项未通过） |
| **J2** 占用×杠杆（样本外选点） | 推荐 `a_allow037__pre`：**守护开启时保持 allowance 0.37** |
| **J3** 冷却档位 | **加长冷却不是收益杠杆** ⇒ 阶梯最高档 24H、默认关闭、定位为风险塑形 |
| **J4** 累计二档 | **证伪**（0.55 首击锁存、0.70 第二次锁存；永久停机应改用已实现亏损口径） |
| **J5** 搜索 | **未找到更优点**（c4 只在收益维度更好，回撤 79.99% 超门；c1 样本外强平） |
| **J6** 结构 vs 熔断 | **首选杠杆：结构（allowance=0）**；两者在"生存"上冗余——结构单独已足够（14.29× / 92.22%），叠加守护把回撤从 92.22% 压到 76.56%，但终值从 14.29× 降到 2.30× |

## 7. 建议（按优先级）

1. **在守护已开启时不要收占用余量**（保持 `we_excess_allowance_pct = 0.37`）：本轮在 ext 与 pre 两条腿上
   都指向同一个结论；收余量只在你决定**不用**账户级熔断、纯靠结构控风险时才划算。
2. **若要用结构单独兜底**：`allowance = 0` + 更低 TWE（本轮 TWE 2.0 的 ext 回撤 61.60% 是全部 allowance=0 臂里最好的），
   并接受更低的终值；这仍然比"无守护 + allowance 0.37"（强平）好得多。
3. **同档杠杆下最值得调的是熔断线，不是冷却时长**：`RED 0.15 + allowance 0` 在 ext 腿上同时给出
   更好的收益（4.30×）与更浅的回撤（56.52%）；而 24/48/72H 全部更差。
4. **永久停机不要用瞬时回撤阈值**：本轮 0.55 与 0.70 都被击穿并造成永久退出；要用就用累计已实现亏损，
   且阈值必须高于存活臂的最差回撤（本轮 76.56%）。
5. **下一轮（引擎级冷却阶梯）按 §6.3 定档**：`halt_ladder_minutes = [720, 1440]`、默认关闭、
   阶梯定位为风险塑形；实现范围（Rust + 实盘重建契约 + 测试矩阵）见 `variant_geometry_design.md` 第 5 节。

## 10. 边界（必须一起读）

- **搜索是样本内的**，而且本轮预算被实测降级到 49 次评估（见 §5）；`c4` 这类"收益更好、回撤更深"的点
  只能读作 Pareto 点，不能读作"推荐配置"。看到样本外结果后没有再做第二次搜索（预注册）。
- **占用几何由成交账本重建**：在场币数按成交时间戳分段做时间加权，窗口取权益序列首末采样；
  单槽上限是规划时约束，实测会有执行摩擦（最大绝对超出 0.0191，已逐臂报告）。
- **实现亏损刹车的机制归因未测量**：backtest 不导出 `loss_gate_blocks` 计数，本轮只能报告它与未开启时
  逐笔相同（零效果）。
- **样本量很小**：5.4 年腿一共只有 4–5 次守护触发，档位/阈值类结论都建立在这几次之上；
  `pre` 腿只有 2.4 年，且 2021-05 事件落在闸门预热/首次转正的边界上。
- 币池是活到 2026 年的当前 top40（幸存者偏差）；长腿 2021-04-20 起交易时仅 22 个币有数据。
- 未建模：真实资金费率、滑点枯竭、API 断连、交易所/稳定币对手方风险；引擎不模拟保证金占用。
- 复牌时点（`resume_condition`）本轮**明确排除**，留待后续单独实验。
