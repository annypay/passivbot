## 0. 一句话结论

**"三年收益非常诱人"与"70%+ 浮亏"不是两个可以分别优化的指标，而是同一个量的两端。**
本策略的尾部回撤由静态损失界 `账户回撤 ≈ TWEL × (1 − 资产价值残留比)` 决定。
要同时保住两者，唯一有效的方向是**在同一敞口下改变收益的产生方式**——
拉宽补仓间距让每次补仓更值钱、把平仓阈值推到最紧、以及在趋势确认后停止新增风险敞口。

**同口径下 30% 已经可达。** 已发布的 `trailing_martingale_twel100_ddf060.json`
把 73.16% 压到 **32.92%**（CAGR +37.67%）；本专题实测 `g1_tw090`（TWEL 1.5 → 0.9）
进一步给出 **29.70% MDD / +34.54% CAGR**。

## 1. 初始上限：30% 回撤对应的收益天花板

在满仓成本敞口 `W`、资产价值残留比 `r` 下，`回撤 ≈ W × (1 − r)`。把 `r` 钉在 2025 事件
实测值（约 0.51）：

| 目标回撤 | 可用 TWEL 上限 | 相对基线(1.5)的敞口比 | 本轮实测倍数 |
| ---: | ---: | ---: | ---: |
| 73% | 1.5 | 1.00 | 12.21x（基线） |
| 33% | 1.0 | 0.67 | 2.61x（**已实测**） |
| 30% | 0.9 | 0.60 | 2.42x（**已实测**） |
| 26% | 0.8 | 0.53 | 2.13x（**已实测**） |
| 21% | 0.65 | 0.43 | 1.48x（已实测，`g2_wide_la010_d020`） |

**读法：`r` 不是常数，是这个上限里最脆弱的一环。** 上表的 `r = 0.51` 只是历史最坏观测。
若 `r = 0.2`（资产跌 80%），`TWEL = 0.9` 依然会打出约 72% 的回撤。
**"把头寸压到 30%"只是把一次 −49% 的事件恰好挡在 30% 以内，它并不提供 30% 的上界。**

## 2. 四个原始设想的逐条判定

### 2.1 「等比阶梯」（`entry.double_down_factor`）— 已有，但不是回撤杠杆

| | |
| --- | --- |
| **机制** | 原生存在。补仓量 = 当前持仓 × `double_down_factor`（基线 0.94），配合 `entry.threshold_base_pct`（补仓间距）与 `entry.retracement_we_weight`（0.334，随敞口加深自动拉宽补仓回撤距离） |
| **本轮结论** | **等比阶梯本身几乎不影响最坏回撤。** 0.94 → 0.6 使 MDD 从 32.92% 变到 32.92%（无变化），0.94 → 0.7 反而把 MDD 压到 32.20% 并把 CAGR 抬到 +40.54% |
| **真正有效的是"间距"而不是"系数"** | `threshold_base_pct` 是唯一能单调压低 MDD 的阶梯参数：0.03 → 0.04 → 0.05 给出 29.32% → 26.14%，代价是 CAGR 22.65% → 17.39% |

### 2.2 「增加平仓条件」（`close.*`）— 已有，且本轮找到了一个真实改进

| | |
| --- | --- |
| **机制** | 原生存在且比设想的更丰富：`close.qty_pct`、`close.threshold_base_pct`、`close.retracement_base_pct`、`close.threshold_we_weight`、`close.retracement_volatility_{1m,1h}_weight` |
| **本轮结论（回撤侧）** | **纯平仓路径调参无法压住 73% 的浮亏。** 下跌中价格在成本**下方**，平仓挂单挂在成本上方，根本不成交。平仓参数是**形态**工具，不是**回撤**工具 |
| **本轮结论（收益侧）** | **找到了本轮最好的收益发现。** `g3_cth0000`（`close.threshold_base_pct` −0.0027 → 0.0）把 CAGR 从 +37.67% 抬到 **+44.36%**，MDD 只从 32.92% 升到 33.19%（+0.27pp） |
| **阴性结果** | `close.retracement_we_weight` 在 0 → 0.0005 → 0.001 三点上**逐位无变化**，该参数在本配置下不生效 |
| **分批减仓** | `close.qty_pct` 0.84 → 0.50 使 MDD 略升 0.05pp、CAGR +1.8pp，并把最长水下从 25.6 天压到 **12.1 天**。这是一个真实的结构松紧度 |

### 2.3 「日线 SMA30/60 交叉判定多空」— 不存在，本轮已实现并实测

| | |
| --- | --- |
| **本轮实现** | Rust 新增 `EntryRegimeGateConfig`（`backtest.entry_regime_gate`），Python 侧因果构造日线 SMA 交叉表。闸门是**只读查表**：Python 按"第 D 日的 bar 只能看 D−1 日及更早的日线收盘"算好边界，Rust 逐 bar 二分查找 |
| **语义** | **只拦入场**，绝不动平仓 / panic / unstuck。`block_initial` 拦新仓，`block_reentry` 拦补仓 |
| **实测（`g4_sma20_50`，最优变体）** | MDD **10.52%**，CAGR **+27.82%**，倍数 2.09x，最长水下 **2.9 天**，成交 28,506（对照种子：32.92% / +37.67% / 2.61x / 25.6 天 / 47,857） |
| **实测（`g4_sma30_60`）** | MDD 13.97%，CAGR +27.00%，倍数 2.05x，最长水下 1.7 天 |
| **判定** | **本专题性价比最高的机制：CAGR/MDD 从 1.14 升到 2.64（`g4_sma20_50`）。** 回撤降到种子的三分之一，收益只让出 26%。对比路径止损（`g2_wide_la010_d020`：CAGR/MDD 0.67、水下 463 天），闸门在两端的优势都是数量级的 |
| **闸门在做什么** | `g4_sma30_60_initial_only`（只拦新仓、放行补仓）给出 13.97% / +27.51%，与全闸门的 13.97% / +27.00% **几乎相同**。即**闸门的全部价值来自"不在下跌趋势里开新仓"**，而不是拦截补仓 |
| **结构限制（重要）** | 30/60 日金叉死叉是滞后指标：2025-02 → 2025-04 的暴跌约两个月，死叉通常滞后 1–4 周，**伤害的大部分已经发生**。因此它是**生存**工具（在 2022 类持续熊市里长期禁止新开仓），不是**事件**工具 |
| **闸门的直接测量** | 用基线的 39,701 笔入场逐笔回放闸门：`sma30/60` 放行 **57.3%**，`sma60/120` 放行 50.4%，`sma5/20` 放行 62.0%。即闸门挡掉约 43% 的历史入场机会 |
| **行为切分** | **只拦补仓（`block_initial=False`）几乎等于关掉策略**：MDD 0.69%、CAGR +0.33%、水下 642 天。**必须同时允许首仓与补仓，闸门才是可用的** |

### 2.4 「MFE giveback」— 已原生实现，且已被证据否决

| | |
| --- | --- |
| **机制** | 就是 `close.retracement_base_pct`。MFE/giveback 状态由 `TrailingPriceBundle` 的 `max_since_open` 与 `min_since_max` 承载，见 `passivbot-rust/src/closes.rs::calc_trailing_close_long` |
| **前序证据** | `maxdd_strategy_research_2026-09-14/mfe_research/`：三折 walk-forward + 严格 ablation + 窄邻域联合搜索，结论 `mfe_enabled_for_final_training = false`。OOS 最差 MDD：比较组 6.5479% vs 启用 MFE 6.5468%——**改善约 0.001pp** |
| **判定** | **已否决，本专题不重测。** G3 的 `retracement_we_weight` 扫描同时给出本配置下的阴性结果（逐位无变化） |

## 3c. 多空翻转：SMA 快线在慢线下方时切到做空

**问题**：把「风险关闭时不开仓」改成「风险关闭时做空」，能否抬高收益上限？

**答案：不能。它同时降低收益、抬高回撤。** 但过程中发现了两个必须记录的东西。

### 3c.1 先修正一个前提：本专题之前的做空证据不足以否决这个设想

仓库里唯一的做空证据是 `maxdd_strategy_research_2026-09-14` 的 `B-LS` 轨道，
manifest 标注为 `"locked-candidate stress only"`：**5 币（BTC/ETH/BNB/XRP/SOL）、
6 个月（2026-03-12 → 2026-09-12）、连续对冲**，实测 gain **0.9947x**、adg −0.000029。
既不是 40 币三年，也不是按 SMA 翻转。所以本轮重新做了。

### 3c.2 两个实现陷阱（都实测踩到）

| 陷阱 | 症状 | 修正 |
| --- | --- | --- |
| **短侧几何是未标定的占位值** | 首轮探针用种子的短侧参数（`initial_ema_dist −0.1`、`close.qty_pct 0.05`、`close.threshold_base_pct −0.02`）→ **798,366 笔空头成交**（多头 25,027），MDD 79% | 短侧阶梯改为**从多头腿派生**：除 `initial_ema_dist`（符号随方向）与 `initial_qty_pct`（按名义敞口重标定，使首仓占余额比例相同）外，其余参数逐项镜像。校验脚本 `report_tools/_check_ls_emit.py` 输出零 DIFF |
| **TWEL 是单侧上限，不是组合上限** | `0.9 多 + 0.9 空` = 同余额上 1.8x 毛敞口 → **liquidated=True**，账户在 3,000 天中的第 439 天归零，最终权益 5,000（起点 100,000） | 把两腿放进**同一个预算**：多头保持 0.9，空头按份额（0.35/0.25/0.15/0.10）取值 |

### 3c.3 预算受约束的实测（全窗口，口径 A，40 币）

两腿共用一个敞口预算，多头腿固定为 `g5_tw090_ddf070` 的几何（TWEL 0.9 + ddf 0.7），
翻转闸门 20/50（与 `best_dd_reducer` 同一张表）：

| ---: | ---: | ---: | ---: | ---: | --- |
| 0.35 | 48.55% | +23.92% | 1.903x | 57.6 天 | 双向恶化 |
| 0.25 | 32.51% | +20.38% | 1.745x | 57.6 天 | 双向恶化 |
| 0.15 | 18.53% | +23.31% | 1.875x | 12.5 天 | 回撤仍高于纯多头 |

对照（同一长臂，无空头腿）：

| 配置 | MDD | CAGR | 期末倍数 | 最长水下 |
| --- | ---: | ---: | ---: | ---: |
| `g4_sma20_50`（纯多头 + 同闸门） | **10.52%** | **+27.82%** | 2.089x | 2.9 天 |
| `g5_tw090_ddf070`（纯多头无闸门） | 28.99% | +35.94% | 2.513x | 10.3 天 |

**每一个空头预算都比同长臂的纯多头版本更差，且在回撤与收益两端同时更差。** 唯一的例外是
`g6_bud_g30_60_tw025`（30/60 闸门 + 0.25 预算：30.05% / +27.34%），但它仍未赶上
`g4_sma20_50` 的 10.52% / +27.82%。

### 3c.4 空头腿到底做了什么（来自 bundle 报告的多空归因表）

`long_short_flip` bundle 的深度分析报告（40 币三年，空头预算 0.25）：

| 方向 | 成交数 | 入场数 | 已实现 PnL | 手续费 | 净已实现 PnL |
| --- | ---: | ---: | ---: | ---: | ---: |
| 多头 | 28,885 | 17,476 | +85,702.94 | −3,100.15 | **+82,602.78** |
| 空头 | 11,254 | 3,024 | **−5,512.23** | −1,664.19 | **−7,176.42** |

**空头腿的毛已实现 PnL 是负的**（−5,512 USDT）。它不是为了对冲而牺牲收益的保险腿，
它自己就是亏的：三年里 3,024 次开空，最终净付出 7,176 USDT，同时把组合回撤从
10.52% 推到 32.51%。

### 3c.5 为什么它必然如此（机制，不只是这一轮的数字）

1. **翻转不改变毛敞口上限。** 静态损失界 `回撤 ≈ TWEL × (1 − r)` 约束的是敞口规模，
   不是方向。把敞口从多头挪到空头，上限不变，只是把押注换了个方向。
2. **加密永续有结构性上行漂移。** 同样波幅下，做空的期望收益更低。
3. **回测不建模资金费率。** `src/` 与 `passivbot-rust/src/` 全库检索无 funding 字段。
   空头是付资金费的一方，因此上述空头腿结论**偏乐观**：按空头敞口占余额的份额估，
   10% 年化资金费在三年里就是初始余额的个位数百分点，足以把 −7,176 的已实现亏损
   再放大到量级相当的额外成本。**真实结果只会比这里更差。**
4. **单侧上限 ≠ 组合上限。** 这是本轮最重要的工程发现：
   策略的全部风险契约就是「单侧敞口帽子」，任何多空版本都必须把两腿放进同一个预算，
   否则就是 1.8x 毛敞口，直接强平。

### 3c.6 结论

- **未能提高收益上限。** 空头腿自身亏损，且抬高组合回撤。
- **也没能改善风险调整收益。** 最好的翻转配置在 MDD 与 CAGR 两端都劣于纯多头版本。
- **若要继续这条线**，前提是先推翻 `3c.5` 的三条机制，或者在编码前就建模资金费率；
  否则任何「做空能提高上限」的结论都只是把风险重新贴了个标签。

## 5. 交付判定

- **`MDD ≤ 30%` 且保住全部收益：不可行。** 结构恒等式决定了回撤与收益同源。
- **`MDD ≤ 30%` 且保住约 92% 的 CAGR：可行。** `g1_tw090` 给出 29.70% / +34.54%。
- **回撤砍到三分之一、收益让出四分之一：可行且是本轮最佳答案。** `g4_sma20_50`
  给出 **10.52% MDD / +27.82% CAGR**（CAGR/MDD 2.64），最长水下 2.9 天。
- **收益更高同时回撤更低：可行。** `g3_cth0000` 给出 +44.36% / 33.19%，两端都优于种子。
- **稳健性排序与本轮前沿排序不一致，必须分开陈述。**
  `g5_tw090_ddf070`（口径 A 最优）在 5 倍手续费下回撤反而劣于种子；
  `g3_cth0000`（`g5_ddf070_cth000` 亦然）在两种口径下都保持 +41%~+45% 的 CAGR；
  `g4_sma20_50`（闸门）是唯一在两种口径下都同时降低回撤与收益、且方向一致的机制。
  **若只能推荐一个"兼顾稳健"的配置，答案是闸门，而不是口径 A 下的收益冠军。**
- **诚实边界（必须随任何结论一起给出）**：
  1. 静态降敞口的全部逻辑建立在"2025 事件是历史最坏 `r`"这一假设上，
     它不是回撤上界。若出现 `r = 0.2` 的行情，`TWEL = 0.9` 仍会打出约 72% 的回撤。
  2. 日线趋势闸门是对该假设**部分解耦**的唯一机制，因为它按趋势而非按幅度限制参与度；
     但 30/60 日交叉滞后，对 2025-02 那种两个月内完成的暴跌只能事后响应。
     它的价值是**生存**（避免在持续熊市中不断补仓），不是**事件保护**。
  3. 以上全部为 1 分钟 OHLC 全量 maker 成交假设下的历史模拟，
     不含盘口队列、部分成交、mark-price 强平与真实保证金梯度。
     它们不是未来收益预测，也不是实盘表现。

## 6. 接线与发布：闸门进入 live 路径

本节记录 §3b 之后的落地工作。结论本身没有变化，变化的是**闸门从"仅在回测里存在"变成
"回测与实盘共用同一份判定"**，并据此发布了一个 profile。

### 6.1 为什么必须先接线再发布

在接线之前，`src/passivbot.py::_bot_params_to_rust_dict` 枚举 `BotParams` 字段时**不包含**
`entry_regime_gate`，因此 live 运行的是 `enabled=false`（`is_on` 恒为 true）的版本，
也就是 **~29% 回撤的那一版**。若在这个状态下发布 gated profile，
profile 声明的行为与实际行为不一致。因此顺序是：先接线，再一起发布。

### 6.2 共享判定算术（`src/entry_regime.py`）

原先 `_utc_day_indices` / `_daily_closes_by_utc_day` / `_regime_on_per_day` /
`_invert_regime_table` 四个纯函数在 `src/backtest.py` 内部，live 无法复用。
现抽出为 `src/entry_regime.py`，作为**唯一**的判定算术实现，回测与 live 都调用它。

| 差异点 | 回测 | live |
| --- | --- | --- |
| 日线来源 | 自己的 1 分钟 bar 按 `ts // 86_400_000` 分桶 | `get_candles(timeframe="1d")`，交易所负责收盘口径 |
| 序列末行 | 当日 bar 仍在形成 ⇒ `exclude_forming_last_day=True` | 只含已收盘日，无形成中行 ⇒ `False` |
| 查询日 | bar 时间戳本身 | `utc_ms()` 所在 UTC 日 |

`regime_flag_for_day()` 把查询日作为一行**无收盘价**的空行追加，因此它不可能成为证据，
历史判定也不会被改写（等价性测试第 8 项专门验证这一点）。

**等价性证据**（脚本化重跑，全部通过）：

1. `utc_day_index` 边界一致。
2. `daily_closes_by_utc_day` 200 组随机稀疏序列一致。
3. `regime_on_per_day` 300 组随机（含 NaN 日、缺失窗口、`confirm_days` 0–4）
   与重构前实现**逐位相同**。
4. `regime_flag_for_day` 与表读法一致；未收盘日拒绝；空序列 fail-closed。
5. **冻结数据全量交叉验证**：在本研究使用的冻结数据集
   （`caches/hlcvs_data/binance__40_coins__2023-08-17_to_2026-09-12__8300950b42789a26`，
   1,614,529 根 1 分钟 bar，40 coins，覆盖 1,123 个 UTC 日）上，
   取前 8 个 coin，把**回测自己的逐日判定** `_regime_on_per_day` 与
   **live 读法** `regime_flag_for_day`（喂入真正的 UTC 午夜日序列）逐日对比：

   ```
   day verdicts compared: 8568
   mismatches: 0
   VERDICT: IDENTICAL
   ```

   这是"回测与 live 对同一天给出同一答案"的直接证据，而不只是单元测试里的构造数据。

**实现过程中修正的一个真实不一致**：`regime_table_from_daily_closes` 最初要求日序列
**逐日连续**，而回测的日序列允许缺口。这会让学生在喂入含缺口的序列时抛错，
与回测行为不符。现改为只强制**两条真正必要的约束**：每个 stamp 必须是 UTC 午夜
（否则判定会落在日内），且严格升序。缺口的语义已由下游保证：
缺行的那一天不是证据，任何包含它的 SMA 窗口都不成立，因此读作 risk-off——
与回测一致，无需额外 guard。

### 6.3 因果性再审计（重构后重跑）

`report_tools/audit_gate_causality.py` 在重构后重跑：**PASS**，
`coins audited=8  day comparisons=8984`，7 组几何全部通过，
与独立暴力 SMA 交叉实现逐日一致，边界为 UTC 午夜（首个边界除外，见 §3b）。

### 6.4 fail-closed 与边界

| 情形 | 行为 |
| --- | --- |
| 日线取不到 / 未对齐 / 长度不足 | 该 symbol **不带表**；Rust 把"无表"读作 risk-off ⇒ 拦截新风险 |
| 某侧 `block_initial` 与 `block_reentry` 均为 false | 该侧从不查表，因此**不需要**日线证据，也不因此被判失败 |
| `gate_mode="invert_for_short"` | live **显式拒绝**：那是多空翻转研究模式（§3c 已否决），不是可交易配置 |
| 主参数（`symbol=None`） | 恒为 `enabled=false`：全局参数不能编码某一个 symbol 的市况 |
| panic 路径 | 开仓前清空表缓存：panic 只平不新开，不应携带任何市况 |

缓存按 **UTC 日 + 闸门参数 + symbol 集合** 缓存；只有**整轮完整成功**才写入缓存，
部分失败当轮不缓存，因此瞬时缺数据的 symbol 会在下一个规划周期重试，而不是被锁到次日。

### 6.7 刻意保留的技术债

`entry_regime_gate` 这个 key **继续留在 `backtest.` 之下**。它现在同时是 live 参数，
路径已经不准确；但迁移会破坏**全部已记录证据 bundle 的可复现性**
（每个 bundle 的 `config.json` 与 `research_contract.json` 都按此路径读取）。
因此保留路径并在 `_entry_regime_gate_config` 的 docstring 中标注为刻意债务。
`gate_mode` 与 `approved` 是 applier 内部字段，不是调用方配置。
