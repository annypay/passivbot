## 测试驱动缺陷（已修）

`pytest.ini` 设置了 `asyncio_mode = auto`。live gate 的测试却在**同步**测试函数里用 `asyncio.run` 驱动协程——只要套件里已有运行中的 loop 就会抛错，于是该文件单独跑绿、全量跑红。已改为 `async def` + `await`（36 个函数）；为此没有改动任何产品代码。

另有一个独立缺陷：新加的 `[regime_gate]` 日志行有 7 个参数却只有 6 个 `%s`，一旦有 handler 格式化该记录就抛 `TypeError: not all arguments converted during string formatting`（pytest 的 logging 捕获会格式化）。修掉格式串后，全量红灯从 30 降到 7（全为既有失败）。

## 花了时间的工具陷阱

- **UNC 路径上的 Windows git 不是权威。** 它读不到 POSIX 权限位（会出现假的 `100755 => 100644`，新加的脚本会以 `100644` 入库），并且在 `add` 时做行尾归一化（CRLF 工作区看起来是干净的）。请用 WSL 里的 git 看状态、权限与行尾；仓库的发布内容只以 WSL git 的报告为准。
- **`git credential fill` 需要重定向 stdin。** 用 `cmd /c "git credential fill < file"` 能拿到已存的 `github.com` 凭据；用 PowerShell 管道拿不到。
- **这个 fork 没有 CI。** `annypay/passivbot` 未启用 GitHub Actions（`/actions/workflows` 返回 0 个 workflow），所以本文件记录的所有检查都是本地运行结果。
