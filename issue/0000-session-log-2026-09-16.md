## Test-driver defect (fixed)

`pytest.ini` sets `asyncio_mode = auto`. The live-gate tests drove their coroutine with
`asyncio.run` from *sync* test functions, which raises as soon as the suite already has a
loop running — so the file was green alone and red in a full run. Converted to `async def`
tests with `await` (36 functions); no product code changed for it.

## Tooling notes that cost time

- **Windows git over the UNC path is not authoritative.** It cannot read POSIX modes
  (spurious `100755 => 100644` entries, and newly added scripts landing as `100644`), and
  it normalises line endings on `add` (CRLF worktrees look clean). Use the WSL git for
  status, modes and line endings; the repository's published content is only what the WSL
  git reports.
- **`git credential fill` needs a redirected stdin.** Through `cmd /c "git credential fill
  < file"` it returns the stored `github.com` credential; a PowerShell pipeline returns
  nothing.
- **The fork has no CI.** GitHub Actions is not enabled on `annypay/passivbot`
  (`/actions/workflows` returns zero workflows), so every check recorded in these files is
  a local run.
