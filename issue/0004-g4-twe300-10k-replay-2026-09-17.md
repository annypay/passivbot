# 0004 — g4 门控 profile @ TWE 3.0 / 10,000 USDT 回测（2026-09-17）

这份记录回答一个直接的问题：**把已发布的 g4 门控 profile 的总暴露上限从 1.0 提到 3.0、起始资金从 100,000 降到 10,000 USDT，会怎样？** 并按上一轮的提议加了一条硬底线（HSL `unified` + `red_threshold=0.10`）做对照。

它属于研究记录；实盘相关事项仍在 `0002-binance-live-debug-2026-09-17.md`。

## 结论先行（数字与完整表格见 `backtests/binance/g4_twe300_10k_replay_2026-09-17/twe300_10k_analysis.md`）

1. **TWE 3.0 在本地历史里被强平。** 5.4 年历史压力腿上，账户在窗口开始后 **29.5 天**（2021-05-19 12:53 UTC，五月崩盘当天）触及引擎地板（起始资金的 5% = 500 USDT），回测在该根 K 线终止（`backtest_completion_ratio=1.5%`），全期最差回撤 **95.34%**。在满仓 3.0× 处，**只需 −31.77% 的行情**就会触及地板。
2. **提议的硬底线没有兜住，而且原因可定位。** `twe300_10k_floor__ext` 的 `hard_stop_triggers = 0`：账户级熔断一次都没触发就已经强平（成交笔数与基线逐笔相同，443 笔）。HSL 的触发指标是 `min(raw, EMA)`（`ema_span_minutes=720`），而这次崩塌从净值高点到地板只有几个小时——**一天内完成的崩盘正是它的设计盲区**。
3. **温和窗口会给出误导性的好数字。** 原生 3 年腿上 TWE 3.0 是 8.83×（发布 profile 2.09×），最差回撤 31.60%（发布 10.52%），最长恢复 31 天——看起来只是"更激进"，直到遇到 2021 年那段历史。
4. **硬底线在温和窗口里反而更差**：3 年腿上最差回撤 31.60% → **37.90%**，恢复期 31 → 301 天，CAGR −48.6pp/年。它砍在底部、错过反弹，与 `0003` 的结论一致。
5. **结构性去风险才是有效的**：`we_excess_allowance_pct=0` 把单槽上界从 0.5871 降到 0.4286、总暴露峰值从 3.00 降到 2.82，历史腿**未被强平**（14.29×，最差回撤 92.22%），原生腿回撤降到 23.05%。但 92% 的回撤说明它只是"没死"，不是"安全"。
6. **10,000 USDT 的规模效应已量化**：与 100k / TWE 1.0 相比，10k 的最差回撤系统性深 1.7–2.5pp，CAGR 差异 ±1pp（来自最小下单量/步长取整与费用占比）。
7. **TWE 3.0 让 10k 的实盘准入更宽松**：单笔初始入场 47.56 USDT（TWE 1.0 为 15.85），可入场币数 39/40（TWE 1.0 为 35/40），全部 40 币所需最低余额 13,614 USDT。

## 方法

- 父配置：`backtests/binance/g4_sma20_50_replay_2026-09-16/artifacts/g4_sma20_50.config.json`（sha256 `5c8ab5ed…`，冻结不变）。
- 9 个预注册 arm：3 年腿 4 个（规模对照 / TWE 3.0 / +硬底线 / +allowance=0）、5.4 年腿 5 个（同样四个 + 终止式硬底线）；两条锚点（100k 的发布 profile 与 `0003` 的 5.4 年控制组）以 sha256 钉住、不重跑。
- 每个 arm：冻结配置 → 离线重放（`src/backtest.py`，命中冻结 bundle、无取数标记）→ 逐币实盘准入附录 → 深度分析（仓库报告规范固定骨架 + 研究附录：资本/杠杆/强平几何、强平读数、冲击矩阵、事件窗口、HSL 运行学）→ 独立复算（`verify_variant_report.py` 不 import 渲染器，特别校验强平证据）。
- 跨 arm 综合 `twe300_10k_analysis.md` + `verify_synthesis.py` 独立复核；9/9 arm 与综合全部通过。
- 离线：无网络、无凭据、不启动实盘；所有 arm 关闭逐币成交面板（内存），报告逐 arm 声明。

## 引擎口径（读数字前必须知道）

- `backtest.starting_balance` 初始化模拟账户并驱动全部按余额缩放的仓位。
- 引擎在 `权益 ≤ 起始资金 × liquidation_threshold(0.05)` 时置 `liquidated=true`、把末值钉在地板并**在该根 K 线结束回测**；`balance_and_equity.csv.gz` 是按 `balance_sample_divider=60` 分钟采样的，因此强平 arm 的最后一个采样点会高于地板（本次滞后约 52 分钟）。
- 引擎不模拟保证金占用与分层维持保证金：表中"交易所强平跌幅"只是以 10× 全仓、维护保证金 0.4% 为例的对照（在同样的实测峰值暴露下，−31.77% vs −32.93%）。

## 对实盘决策的影响

- **不要把 TWE 调到 3.0。** 按 J1 的裁决，它在本地历史范围内不可实盘；这不是"回撤更大"的问题，而是"本金被清零"的问题。
- **硬底线不能替代低杠杆。** `unified` red=0.10 在这次崩盘里 0 次触发；要真正封住尾部，只能压低暴露上界（TWE / `n_positions` / `we_excess_allowance_pct`）或降低资金规模。
- **若一定要更激进**：先做 `we_excess_allowance_pct=0`（结构性、不需盯盘），并接受仍然 ~90% 量级的极端回撤；任何进一步加杠杆都需要新的证据。
- 本记录不改发布 profile；若决定修订，另开 profile PR 并同步 `docs/strategy_profiles.md` 与 `0002` 的启动清单。

## 待办与后续

- 若要考虑"在强平之前介入"的机制，需要的是**比 EMA 更快**的触发（例如基于未实现亏损的相对阈值）或**结构性上限**，而不是现有 HSL 参数；这属于引擎级改动，必须先开设计讨论。
- 10k 实盘上线前用 `passivbot tool entry-regime-probe --balance 10000` 复核当前真实准入（公开行情、无凭据）。
