# 0006 — g4 @ TWE 3.0 风险几何优化：占用纪律、冷却档位与参数搜索（2026-09-17）

这份记录回答：**在 `0005` 已经证明「一周 −20% 熔断 12H 能救回账户、但 3 年腿要放弃约 30% 终值」之后，
能不能用引擎已有的旋钮把这份生存买得更便宜？** 具体是用户提出的两条路径——**占用纪律**
（`we_excess_allowance_pct = 0`，不让任何币占用空槽的额度）与**把阶梯接在冷却时长上**——
加上一次"只搜风险几何、钉死 alpha"的参数搜索，并用一个**样本外窗口**验收搜索结果。

它属于研究记录；实盘相关事项仍在 `0002-binance-live-debug-2026-09-17.md`。

## 结论先行（数字与完整表格见 `backtests/binance/g4_twe300_risk_optimization_2026-09-17/risk_geometry_analysis.md`）

1. **占用纪律在机制上完全生效，但与守护叠加时在崩盘腿上更差。**
   allowance 0.37 → 0 把单币上限从 **0.5871 压到 0.4286**、单币归零上界从 **59.15% 压到 44.34%**、
   温和 3 年窗最差回撤从 **30.19% 压到 23.05%**（TWE 2.0 时 **17.75%**）；但在同档杠杆（TWE 3.0）的
   5.4 年腿上，它让终值从守护基准的 **7.8552× 掉到 2.3002×**、最差回撤从 **62.40% 升到 76.56%**。
   **在场币数几乎不变（2.86 vs 2.87）**——收余量改变的是每个币的**大小**，不是持有的**数量**。
2. **判据 J1 判定占用纪律"无效"**：四项预注册检查里集中度两项（峰值单币敞口、单币归零上界）通过，
   终值与回撤两项未通过。机制：更紧的单币上限让每次清仓后的重建更慢，并改变权益路径、
   推迟守护触发时点，于是崩盘腿回撤反而更深。
3. **判据 J2（样本外选点）推荐"守护开启时保持 allowance 0.37"**：pre 腿上
   `allowance 0.37`（1.2506× / 62.40%）优于 `allowance 0`（0.6104× / 76.56%）与
   `TWE 2.5 + allowance 0`（0.4242× / 80.14%）。
4. **两条保护是替代品，不是叠加品（J6）**：无守护时 allowance=0 就是救命的那一条
   （14.29× / 92.22%，未被强平，而 allowance 0.37 被强平）；有守护时 allowance 0.37 更好。
   叠加把回撤从 92.22% 压到 76.56%，但终值从 14.29× 降到 2.30×。
5. **冷却档位再次证伪（J3）**：24H/48H/72H 在 ext 与 pre 两条腿上都不优于 12H
   （ext 2.77×/2.08×/1.87× vs 2.30×，pre 0.59×/0.56×/0.48× vs 0.61×）。
   ⇒ 下一轮引擎级阶梯最高档取 **24H**，并明确定位为"风险塑形、默认关闭"。
6. **累计永久阈值依旧危险（J4）**：`no_restart_drawdown_threshold=0.55` 在 ext 腿**首击锁存**
   （终值 0.3399×），0.70 在第二次触发锁存（0.2910×）；而同一几何下不锁存的臂最差回撤是 76.56%。
   **任何低于存活臂最差回撤（约 0.77）的永久地板在这段历史里都等于自杀**；永久停机应改用
   **累计已实现亏损**口径。
7. **实现亏损刹车零效果**：`live.max_realized_loss_pct=0.50` 的 ext 腿读数与未开启**逐笔相同**
   （45,644 笔成交签名一致）——它没有约束到任何一笔平仓，不能当作已验证的保护。
8. **同档杠杆下最值得调的是熔断线**：`allowance=0 + RED 0.15` 是 allowance=0 家族里的最优点
   （ext 4.3033× / 56.52%，同时优于该家族 12H 基准的 2.3002× / 76.56%）。
9. **参数搜索找到了样本内最优、但它在样本外被强平（J5）**：搜索窗 ADG 最高的候选 `c1`
   （TWE 2.8 / 6 槽 / allowance 0.21 / RED 0.30 / EMA 75 / 停 72H）在 3 年窗是 7.2577× / 25.01%，
   在 ext 与 pre 两条腿**都被强平**（0.7118× / 95.31%，0 次触发）。另一个候选 `c4`
   在 ext/pre 的收益都超过守护基准（9.0111× / 1.7789× vs 7.8552× / 1.2506×），但回撤 79.99% 超过
   预注册的 50% 门 ⇒ 按规则记作 **Pareto 点**而非更优解。**预算如实降级**：声明预算 1024 次评估 /
   2 worker 在本机不可行（冒烟测：49 次评估耗时 **12.6 小时**、峰值 RSS **6196 MB**，
   最后 8 次评估在内存压力下耗时 12 小时），因此本轮用**冒烟测的 49 次评估 Pareto 前沿**
   按**未改动的选臂规则**冻结了 4 个候选（`c1`–`c4`）并在报告与本记录中标注。

## 方法

- 父配置：`backtests/binance/g4_sma20_50_replay_2026-09-16/artifacts/g4_sma20_50.config.json`
  （sha256 `5c8ab5ed…`，冻结不变）；上一轮的守护形状（`unified` / RED 0.20 / EMA 60 / 停 12H）
  作为本轮所有臂的守护基准。
- **三条腿**：`3y`（2023-09-12 → 2026-09-12，**搜索窗，样本内**）、`ext`（2021-04-20 → 2026-09-13，
  全历史，含搜索窗）、`pre`（2021-04-20 → **2023-09-11**，用 `intersection` override 从同一份长 bundle
  切出，**与搜索窗不重叠，是唯一的样本外验收窗**）。
- **占用纪律网格**（守护固定 12H）：allowance ∈ {0, 0.10, 0.20, 0.37}、TWE ∈ {3.0, 2.5, 2.0}；
  `n_positions=7` 在这两个阶段不变，以便把"占用"与"槽位"分开读。
- **守护几何/档位**（allowance=0）：冷却 12/24/48/72H、累计阈值二档（0.55 / 0.70）、
  实现亏损刹车（0.50）、EMA 15 分钟、RED 0.15。
- **参数搜索**：仓库既有 pymoo 优化器，只在 `3y` 腿上跑；搜索域恰好是六个风险几何维度，
  用 `-ft/--fine-tune-params` 把其余全部 bounds 固定到当前配置值（hydration 会展开引擎默认 bounds，
  只有 `-ft` 能挡住），并用日志里的 tunable/fixed 集合做门；双目标
  （ADG 最大 / 最差回撤最小）+ 参考约束（回撤 >0.60、completion <0.99 惩罚）；
  选臂规则在看到样本外结果之前执行并冻结，候选在三条腿上各重放一次。
- 每个 arm：冻结配置 → 离线重放（命中冻结 bundle、无取数标记）→ 深度分析（固定骨架 + 研究附录：
  账户守护读数、整装待发读数、**暴露几何与占用纪律**、**参数搜索与选择轨迹**、**样本外读数**）
  → 独立复核（`verify_variant_report.py` 逐行复算停机窗口与几何，不 import 渲染器）。
- **44/44 arm 与综合全部通过独立复核**（`verify_synthesis.py` 复核 50 列，含 6 条钉住参考臂）。
- 离线：无网络、无凭据、不启动实盘；逐臂关闭逐币成交面板（内存），报告逐臂声明。

## 引擎口径（读数字前必须知道）

- 单币上限 = `TWE / n_positions × (1 + effective allowance)`，bounded 模式把 effective allowance
  夹到 `min(raw, TWE/(TWE/n) − 1)`（本域内 = `n_positions − 1`，不 binding）。
- 上限是"下单规划时"的约束；成交账本记录成交时的 `wallet_exposure`，盯市漂移与**最小下单量**
  会让实测略高于上限。本轮 32 个声明式臂里最大绝对超出 **0.0191**、相对最高 **+5.47%**
  （最紧的上限 TWE 2.5/7）；几何不变量用 `上限 × 1.05 + 0.02` 校验，造成超出的成交记在
  `risk_geometry.json::cap_overshoot_fill`。
- `no_restart_drawdown_threshold` 的锁存判定在**平仓确认那一刻**、用 `max(raw, EMA)`；
  本轮实测 0.55 与 0.70 都会在这段历史里锁存。
- `live.max_realized_loss_pct < 1` 拦截**非 panic** 亏损平仓（panic 豁免），backtest 不导出拦截计数，
  该臂只能报终值/回撤/成交差异，机制归因属于未测量部分。
- 搜索预算降级的证据：`artifacts/search_smoke.json`（49 次评估 / 12.6 h / 6196 MB）+
  `artifacts/search_record.json`（离线门与搜索域门全部通过）。

## 对实盘决策的影响

- **守护已开启时不要收占用余量**：保持 `we_excess_allowance_pct = 0.37`；收余量只在"不用账户级熔断、
  纯靠结构控风险"时才划算（那种组合本轮/上一轮都实测为存活：14.29× / 92.22%）。
- **同档杠杆下先调熔断线，再考虑其它**：`RED 0.15 + allowance 0` 在历史腿上同时改善收益与回撤
  （4.3033× / 56.52%），比拉长冷却有效得多。
- **不要用瞬时回撤做永久地板**；**不要指望实现亏损刹车**（零效果）；**不要用 TWE 3.0 实盘**。
- 本记录不改发布 profile；若决定改守护参数，另开 profile PR 并同步 `docs/strategy_profiles.md`
  与 `0002` 的启动清单。
