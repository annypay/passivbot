# 0003 — g4 尾部风险研究：单币/多币归零与账户级熔断（2026-09-17 起）

这份记录回答一个具体担忧：**"马丁格尔最后总会被一波带走"——在已发布的 g4 门控 profile 上，这件事在本地数据的范围内会不会发生？开着 HSL 会不会更容易发生？`pside`/`unified` 组合级信号是否值得上？**

它属于研究记录，不是实盘操作记录；实盘相关的事项仍在 `0002-binance-live-debug-2026-09-17.md`。

## 结论先行（细节与数字见 `backtests/binance/g4_tail_risk_research_2026-09-17/tail_risk_analysis.md`）

1. **"一个币归零带走全部本金"在引擎层面不成立。** 单槽敞口上界 = `TWEL/n_positions × (1 + we_excess_allowance_pct)` = `1.0/7 × 1.37` = 0.19571；合成注入（A 臂：把控制组里敞口最大的币 AAVE 在其敞口峰值那一分钟起、3 天内压到 0.005×）实测：全期最差回撤 10.52% → **18.09%**，注入窗口内最大回撤 **17.62%**，窗口收益仍为 **+0.57%**，**17.8 天恢复**，无 panic、无强平。按实测敞口峰值，−20%/−50%/−80% 分别需要 **2/3/5** 个币同时归零。
2. **真正的尾部是"多币/慢磨"回撤。** 5.4 年历史压力腿上，同一份配置实测总暴露峰值达到 **1.000002**（某一刻账户满仓），全期最差回撤 **41.31%**、最差 1% 均值回撤 18.10%——同一配置在原生 3 年窗口只有 10.52% / 6.85%。"历史三年很温和"不能外推。
3. **HSL（含 `pside`/`unified`）没有买到尾部保护，只卖出了收益。** 5.4 年腿上：`coin` 2.32×（−28% 终值、回撤不变）、`pside_r15`/`unified_r15` 2.64×（−18%、回撤不变）、`unified_r10` 2.84×（−12%、回撤不变）、`unified_r10_fast` 1.83×（唯一把回撤降到 39.18%，但最差 1% 均值回撤从 18.1% 翻倍到 36.9%、恢复期 1033 天）、`unified_r10_never` **0.80×**（−75%）。原生 3 年腿上 `pside`/`unified` 在 0.15 甚至 0.10 下**完全不触发**。
4. **HSL 不能防插针/跳空。** 触发指标是 `min(raw, EMA)`（引擎注释表明这是为了避免"闪崩底部离场"），对一天内完成并反弹的行情天然迟钝。
5. **唯一"确定"压低尾部的是结构性去风险。** `we_excess_allowance_pct=0`：单币上界 19.57%→14.29%，5.4 年最差回撤 41.31%→**30.78%**、最差 1% 均值回撤 18.10%→**9.58%**，代价是终值 −24%。`twe_090` 与 `total_exposure_enforcer` 只改善一个指标、恶化另一个（后者把最差 1% 均值回撤推到 37.4%）。
6. **`live.max_realized_loss_pct` 不是止损开关。** 它拦的是"实现亏损的平仓单"（panic 除外）；在本配置下设 `0.5` **与基线逐位相同**（unstuck 的止损额度太小、从未撞到门槛），在别的配置里设小则可能阻止 unstuck 减仓、把仓位钉在最大暴露上（`docs/risk_management.md` §C 原文警示）。

## 方法

- 父配置：`backtests/binance/g4_sma20_50_replay_2026-09-16/artifacts/g4_sma20_50.config.json`（sha256 `5c8ab5edad9b571c…`）。
- 两条真实腿：原生 3 年（`2023-09-12 → 2026-09-12`）与历史压力 5.4 年（`2021-04-20 → 2026-09-13`，同一 40 币冻结 bundle 的 `dataset` override）；一条合成腿（原生 bundle 的派生副本 + 注入的崩塌价格路径）。
- 27 个 arm 全部先在 `artifacts/variant_input.json` 注册（声明式改动 + 判据 J1–J4 + 事件规则 + 冲击水平），再运行；`build_variant_config.py` 与 `run_variant.py` 双向断言"冻结配置 = 父配置 + 声明改动"。
- 每个 arm 的深度分析写在自己的 run 目录里（仓库报告规范固定骨架 + 研究附录：暴露上界、冲击损失矩阵、事件窗口表、HSL 运行学、边界、实盘读数）；跨 arm 综合写 `tail_risk_analysis.md`；`verify_variant_report.py` / `verify_tail_risk_synthesis.py` 不 import 渲染器，独立复算。
- 离线：无网络、无凭据、无交易所账户、不启动实盘进程。

## 已知边界（写进报告正文，不隐藏）

- 本地数据最早 2021-03，币池是"活到 2026 年的当前 top40"（幸存者偏差）；2021-04-20 起才有交易，当时仅 22 个币有数据。
- 2021-05 事件落在闸门首次风险开启（2021-05-14 首笔成交）之后 3 个交易日，属"最差入场"，只能作旁证。
- 合成注入是价格路径注入，不含撮合、交易所公告、退市流程与真实流动性；报告单独标注"合成"。
- 未建模：交易所/稳定币对手方风险、真实期权与资金费率、真实滑点枯竭、API 断连。

## 对实盘决策的影响

- 这份研究**不改变 0002 的入金结论**，但改变"上了实盘之后靠什么兜底"的答案：单币归零不需要兜底（结构性有界），需要兜底的是多币/慢磨回撤，而账户级熔断在这个策略上**买不到**回撤保护。
- 默认建议：**保持 HSL 关闭**（发布 profile 的现状）；若确需一条硬底线，用 `unified` + `red_threshold=0.10`（最便宜的账户级档，5.4 年 ΔCAGR −3.0pp/年），不要用 `restart_after_red_policy=never`。
- 若要把尾部压低到 31% 量级：`we_excess_allowance_pct=0.37→0`，代价约 −24% 终值——这是配置层取舍，必须另开 profile 修订 PR（配置 + 文档 + 追溯），不在本记录里直接改。
- 若启用 `pside`/`unified`：**不得使用 `live.balance_override`**（`docs/equity_hard_stop_loss_risks.md`），并在上实盘前用 `passivbot tool live-config-preflight` 与 `hsl-startup-preview` 验证账户状态。
- 实盘只看三个数：`total_wallet_exposure`（到 1.0 = 整篮满仓）、策略净值回撤（−20% 为复核线）、闸门状态。
